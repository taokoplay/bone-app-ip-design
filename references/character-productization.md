# App IP 产品化分支

仅当任务涉及母体选择、角色/物件/系统产品化、状态或换装时读取。正式输出格式读取 `deliverable-templates.md`。

## 1. IP 母体决策

先保留“无新增 IP”作为基线，再选择一个主母体；Hybrid 最多增加一个辅助母体，不能让两个识别中心争夺注意力。

| 母体 | 身份来源 | 执行内容 | 跳过内容 |
|---|---|---|---|
| Character | 轮廓、脸、姿势、人格 | 职位、基础母版、表情、状态、换装 | — |
| Object | 被英雄化的核心物件 | 功能动作、部件、轮廓、材质、状态 | 无必要的脸、服装 |
| Abstract / System | 形状、空间、节奏、运动规则 | 形状语法、运动语法、密度、状态映射 | 眼鼻嘴、肢体、换装 |
| Typographic / Attitude | 字形、名称、语气、反品类立场 | 字重、字距、宽度、基线、响应与尺寸 | 裸模、骨架、服装 |
| Hybrid | 一个主身份 + 一个辅助系统 | 明确主次和共用规则 | 双主角、双超级符号 |

### 是否需要人格化角色

在选职位前问：角色是否比普通 UI、copy、动效或核心物件更有效？已有强母品牌、严肃工具或高密度工作流可以只做 Object/System/Typographic，或不新增 IP。

## 2. 产品职位与人格行为

Character 主职位选 1 个，副职位最多 1 个：状态播报、陪伴、导航、成就见证、品牌代言、收集/装扮载体。

写清：何时出现、何时闭嘴、成功如何表达、失败绝不做什么。人格词必须行为化：

```text
关键词：
表现为：
不表现为：
高压场景下：
动作/语气强度：
```

健康、习惯、提醒、财务、学习、儿童等高压力结果默认不责备、不羞辱、不卖惨。若产品明确采用强刺激语气，先确认边界。

## 3. 三方向发散

三个方向要跨越不同联想距离，而不只是换物种或换色：

1. **直译型**：核心物件或行为，品类理解最快。
2. **隐喻型**：用户心理、关系或最终结果。
3. **系统/反常识型**：抽象规则、矛盾组合或品牌态度。

每个方向记录：母题、联想距离、为何不是品类默认答案、主识别机制、次级确认特征、备用识别来源、产品场景、误读风险和 32/64/96pt 预判。

一个**主识别机制**可由 1–3 个彼此依赖的结构组成，但不能有多个互抢注意力的中心。

筛选先定义项目权重，再以 1–5 分评估：小尺寸、产品连接、无装饰身份、状态能力、货架差异、扩展成本、无障碍和原创风险。64pt 与原创高风险属于硬门槛，其余按项目目标加权。

## 4. 基础母版

先建立**去除非结构性装饰的基础母版**：

- 装饰性配件：移除后验证身份。
- 结构性身份组件：壳、容器、面罩、共生结构可保留，但写入母版不变量。
- 功能性道具：分别验证“有道具身份”和“无道具最低识别”。

### Character 锁定

- 头身比与轮廓
- 脸部坐标
- 主识别机制
- 肢体连接
- 表现媒介和基础色职责

### Object 锁定

- 核心轮廓和负形
- 功能部件与连接
- 开合/填充/工作姿态
- 材质和尺度感

### Abstract/System 锁定

- 基础几何与组合语法
- 形变边界
- 运动节奏与空间关系
- 密度、轨迹和颜色职责

### Typographic 锁定

- 字形骨架、字重和宽度
- 字距、基线、标点
- 小尺寸图形块
- 语气和响应规则

正式扩展要等母版确认；概念阶段可为每个候选做一个高风险状态和一个极端扩展的低成本探针，不进入事实源。

## 5. 表现媒介与 App 联调

不要默认潮玩 3D。按产品选择：扁平、线性、单色 Glyph、像素、剪纸/拼贴、手绘、程序化几何、纯运动系统、软胶、搪胶、树脂、透明材质或混合媒介。

颜色按职责定义：Brand Primary、IP Body/Core、Structure Dark、Surface Light/Dark、Emotion/State Accent。品牌色不必涂满主体。

至少验证：浅色界面、深色界面、品牌色卡片、32/64/96pt、主操作层级、灰阶和关键状态的非颜色编码。未实际生成或检查时标记“待工具执行”，不能声称通过。

## 6. 业务状态协议

先按责任主体分类：

| 类别 | 示例 | 关键问题 |
|---|---|---|
| 用户结果 | completed / skipped / missed / milestone | 不羞辱；给恢复路径 |
| 系统执行 | loading / syncing / offline / error / blocked | 不暗示用户有错；明确下一步 |
| 内容 | empty / no-result / first-use | 空不等于失败 |
| 关系 | idle / returning / waiting | 避免持续打扰 |

每个状态记录：责任主体、触发条件、用户下一步、IP 表达、UI/文案职责、禁止行为、动效时长和 reduced-motion fallback。系统 `error` 不与用户 `missed` 合并。

### 不同母体的表达通道

- Character：表情、姿势、视线、局部动作。
- Object：开合、旋转、填充、功能部件和工作姿态。
- Abstract/System：形变、节奏、密度、空间、轨迹。
- Typographic：字重、宽度、字距、基线、标点和语气。

角色不能承担系统控件、错误恢复或法律披露应承担的信息。

## 7. 换装和主题成本分级

- **Tier A 轻装**：轮廓变化小，完全复用骨架。
- **Tier B 主题装**：允许局部轮廓变化；保留主识别机制，声明遮挡和碰撞规则。
- **Tier C 变体形态**：允许显著变化；至少保留两个身份锚点，可使用独立动画资产。

骨架复用是成本决策，不是绝对创意禁令。核心状态反馈不得被付费破坏。

## 8. 原创性与商用快速筛查

检索同品类 App、角色 IP、玩具/盲盒、商标图形和用户点名参考；比较整体轮廓、脸部布局、主识别机制、配色组合、名称、典型姿势和服装组合。

- 低：只有抽象原则相似。
- 中：两个以上核心组合接近，必须重构并复查。
- 高：整体印象、名称或独特组合近似，停止使用。

保存查询词、日期、链接/截图和判断理由。快速筛查不替代商标、版权或法律意见。

## 9. 行为可用性验证

除静态测试外，至少规划：5 秒状态理解、高频重复 10 次干扰、失败状态责备感、触控/手势遮挡、动效后可操作性、VoiceOver 装饰性/语义性标注和 reduced motion。只有实际执行的项目才能标记已验证。
